## 断边死信（lineage-v2）

扫描发现的断边不再混在活关系里：

- **命运只兑现一种——旁路账册死信凭证**：断边在主表置「已死信」并从影响 BFS、覆盖统计中隔离，
  同时在 `dead_letter_vouchers` 账册写凭证，记全量 sha256 边指纹（`edge_code|上游|下游|变换`）供日后核齐。
  「独立队列吞没」模式不实现、不可并存，台参数 `dead_letter_mode` 只读锁定。
- **串行闸**：送死信在 `BEGIN IMMEDIATE` 库级写锁内一次落库，待核齐凭证对 fingerprint / edge_id
  各建部分唯一索引；两名值班抢送同一边只落一张凭证，后到者收中文业务错误。
- **扫描去重入库**（`POST /api/dead-letters/scan-ingest`）：健康边入草稿、断边写凭证、
  扫描指纹与现行边对不上即拦截（中文原因），同指纹重复扫描幂等不双写。
- **页面对照**：死信页显示命运来源（人工送死信/扫描断边）与凭证指纹，并附节点目录编码对照；
  影响页显示隔离条数（待核齐凭证数）；覆盖页报告含死信隔离数，未核齐时顶栏 chip 显示「死信待核」不虚绿。
- **核齐**（`POST /api/dead-letters/<id>/reconcile`）：端点节点恢复且现行边指纹与凭证一致才可核齐，
  凭证关闭、边复活为草稿。
